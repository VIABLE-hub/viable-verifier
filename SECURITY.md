# Security reporting

Report suspected vulnerabilities privately to **hello@viable-id.com**, identifying the repository and affected version/commit. Start with a short description and redacted reproduction steps; arrange a suitable private channel before sending sensitive evidence.

Do not put credentials, private keys, personal data or an exploit against a live service into public issues. Use an isolated environment and synthetic data for reproduction. No response-time SLA or bug-bounty payment is implied.

For VIABLE maintainers: coordinate triage with Adam and Patrick, preserve evidence, assess affected releases and consumers, and document remediation. Proof/credential trust changes require qualified review. Keep private configuration out of documentation examples.
